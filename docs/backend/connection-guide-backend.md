## Architecture Overview

```
integrations.json  ← generated by: wp zaplane build:integration
        ↓
ZaplaneGlobal.integrations  (PHP → JS via wp_localize_script)
        ↓
Workflow editor (React) reads requires_connection, triggers, actions, schema

At runtime (workflow execution):
  WP hook fires  →  Automation::trigger_router()
                       → Run::create()
                       → NodeRun::create()  (per node)
                       → inject_credentials()  (reads connection_id from node data)
                       → Integration::execute_node($node, $input)
```

## Creating an Integration

Extend `Zaplane\Framework\Classes\IntegrationBase` and place your file in `integrations/`:

```php
<?php
namespace Zaplane\Integrations;

use Zaplane\Framework\Classes\IntegrationBase;

class MyApp extends IntegrationBase {
    public static function get_slug(): string { return 'myapp'; }
    public static function get_name(): string { return 'My App'; }
    public static function get_icon(): string { return 'myapp'; }
    public static function get_category(): string { return 'app'; } // 'app' | 'tool'
}
```

Register it in `includes/config/integrations.php` under the `registry` key:

```php
'myapp' => [
    'file'  => 'myapp.php',
    'class' => \Zaplane\Integrations\MyApp::class,
],
```

Then regenerate the manifest: `wp zaplane build:integration`

## Triggers

Triggers are WordPress hooks that start a workflow. Define them in `get_triggers()`:

```php
public static function get_triggers(): array {
    return [
        'user_signup' => [
            'label' => 'User Signed Up',
            'hook'  => 'user_register',   // any WP hook
        ],
    ];
}
```

### Naming convention for webhook triggers
Triggers that fire from incoming webhooks must follow: **`{slug}_webhook_{event}`**

```php
'message_received' => [
    'label' => 'Message Received',
    'hook'  => 'slack_webhook_message',
],
```

### Resolving trigger data

`resolve_trigger()` converts raw WP hook arguments into a structured payload:

```php
public static function resolve_trigger( array $node, array $hook_args ) {
    $post_id = $hook_args[0] ?? 0;
    $post    = get_post( $post_id );
    if ( ! $post ) return false;  // return false to skip this execution

    return [
        'post_id'    => $post->ID,
        'post_title' => $post->post_title,
        'post_url'   => get_permalink( $post->ID ),
    ];
}
```

Return `false` to abort the run. Return an array to pass as the first node's input.

### Trigger config schema

Optionally expose UI fields (e.g., a post type filter) via `get_trigger_config_schema()`:

```php
public static function get_trigger_config_schema( string $trigger ): array {
    if ( $trigger === 'publish_post' ) {
        return [
            'post_type' => [
                'type'    => 'select',
                'label'   => 'Post Type',
                'dynamic' => [ 'query' => 'post_types', 'select' => ['value', 'label'] ],
            ],
        ];
    }
    return [];
}
```

## Actions

Actions are nodes in the workflow graph that do work. Define them in `get_actions()`:

```php
public static function get_actions(): array {
    return [
        'send_email' => [ 'label' => 'Send Email' ],
        'create_post' => [ 'label' => 'Create Post' ],
    ];
}
```

### Action config schema

Define the fields the user fills in the workflow editor:

```php
public static function get_action_config_schema( string $action ): array {
    if ( $action === 'send_email' ) {
        return [
            'to'      => [ 'type' => 'text',     'label' => 'To',      'required' => true ],
            'subject' => [ 'type' => 'text',     'label' => 'Subject', 'required' => true ],
            'body'    => [ 'type' => 'textarea', 'label' => 'Body' ],
        ];
    }
    return [];
}
```

#### Field types

| type | Description |
|------|-------------|
| `text` | Single-line text, supports `{{variable}}` tokens |
| `textarea` | Multi-line text |
| `number` | Numeric input |
| `email` | Email input |
| `url` | URL input |
| `password` | Masked input (never echoed in logs) |
| `select` | Dropdown — provide `options: [{value, label}]` or a `dynamic` query |
| `date` | Date picker |
| `condition_group` | Visual condition builder |

### Executing the action

```php
public static function execute_node( array $node, array $input ): array {
    $action      = $node['config']['action'] ?? '';
    $credentials = $node['_connection_credentials'] ?? [];  // injected automatically

    if ( $action === 'send_email' ) {
        $to      = $node['config']['data']['to']   ?? $input['email'] ?? '';
        $subject = $node['config']['data']['subject'] ?? '';

        wp_mail( $to, $subject, $node['config']['data']['body'] ?? '' );

        return [
            'port' => 'main',
            'data' => array_merge( $input, [ 'email_sent' => true ] ),
        ];
    }

    return [ 'port' => 'main', 'data' => $input ];
}
```

**Return format:**

```php
[
    'port' => 'main',   // which output port — matches an edge's sourceHandle
    'data' => [...]     // passed as input to the next node
]
```

For conditional branching return different `port` values (`'yes'` / `'no'`, `'match'` / `'no_match'`, etc.) and define them in `get_output_ports()`:

```php
public static function get_output_ports(): array {
    return [ 'yes', 'no' ];
}
```

## Connection & Authentication

### Requiring a connection

```php
public static function requires_connection(): bool { return true; }
public static function get_auth_type(): string { return 'api_key'; } // see table below
```

### Defining auth fields

```php
public static function get_auth_fields( ?string $auth_type = null ): array {
    return [
        'api_key' => [
            'type'     => 'password',
            'label'    => 'API Key',
            'required' => true,
            'help'     => 'Found in your app settings → API.',
        ],
    ];
}
```

### Testing the connection

```php
public static function test_connection( array $credentials ): array {
    [ $body, $status ] = self::http_get(
        'https://api.myapp.com/me',
        [ 'Authorization' => 'Bearer ' . ( $credentials['api_key'] ?? '' ) ]
    );

    return [
        'success' => $status === 200,
        'message' => $status === 200 ? 'Connected as ' . $body['name'] : 'Failed',
        'details' => $body,
    ];
}
```

### How credentials reach execute_node

When a workflow node has `connection_id` set in its data, the Automation engine calls
`ConnectionManager::get_execution_credentials($connection_id)` before passing `$node`
to `execute_node()`. The decrypted credentials are injected as `$node['_connection_credentials']`.

**You never need to fetch credentials manually — just read `$node['_connection_credentials']`.**

### OAuth 2.0

Implement these methods to support the full OAuth flow:

```php
public static function get_oauth_auth_url( string $redirect_uri, string $state, array $credentials = [] ): ?string {
    return 'https://auth.myapp.com/oauth?' . http_build_query([
        'client_id'    => $credentials['client_id'],
        'redirect_uri' => $redirect_uri,
        'state'        => $state,
        'scope'        => implode( ' ', self::get_oauth_scopes() ),
    ]);
}

public static function exchange_oauth_code( string $code, string $redirect_uri, array $credentials = [] ): array {
    [ $body ] = self::http_post( 'https://auth.myapp.com/token', [
        'code'          => $code,
        'client_id'     => $credentials['client_id'],
        'client_secret' => $credentials['client_secret'],
        'redirect_uri'  => $redirect_uri,
    ]);

    if ( empty( $body['access_token'] ) ) {
        throw new \Exception( 'Token exchange failed' );
    }

    return [
        'access_token'  => $body['access_token'],
        'refresh_token' => $body['refresh_token'] ?? null,
        'expires_in'    => $body['expires_in']    ?? null,
    ];
}

public static function get_oauth_scopes(): array {
    return [ 'read', 'write' ];
}
```

## Incoming Webhooks

When an external service needs to POST events to Zaplane:

**Endpoint:** `POST /wp-json/zaplane/v1/incoming/{slug}`

### Step 1 — Enable webhook support

```php
public static function supports_webhook(): bool { return true; }
```

### Step 2 — Verify the signature

```php
public static function verify_webhook_signature( \WP_REST_Request $request ): bool {
    $secret    = get_option( 'myapp_webhook_secret', '' );
    if ( empty( $secret ) ) return true;  // dev mode — skip validation

    $signature = $request->get_header( 'x-myapp-signature' ) ?? '';
    $expected  = 'sha256=' . hash_hmac( 'sha256', $request->get_body(), $secret );

    return hash_equals( $expected, $signature );
}
```

Return `false` → HTTP 401. Return `true` → continue processing.

### Step 3 — Parse the event

```php
public static function parse_webhook_event( \WP_REST_Request $request ): ?array {
    $body = $request->get_json_params();

    // Return null to accept HTTP but NOT trigger any workflow.
    // Use this for URL verification challenges, pings, etc.
    if ( ( $body['type'] ?? '' ) === 'ping' ) {
        return null;
    }

    $map = [
        'subscriber.added'   => 'subscriber_added',
        'subscriber.removed' => 'subscriber_removed',
    ];

    $event = $map[ $body['event'] ?? '' ] ?? null;
    if ( ! $event ) return null;

    return [
        'event'   => $event,         // must match a key in get_triggers()
        'payload' => $body['data'],  // passed to resolve_trigger() as $args[0]
    ];
}
```

### Step 4 — Handle in resolve_trigger

When triggered via webhook, `$hook_args[0]` is the `payload` from `parse_webhook_event()`:

```php
public static function resolve_trigger( array $node, array $hook_args ) {
    return $hook_args[0] ?? [];
}
```

### Get the webhook URL

`GET /wp-json/zaplane/v1/incoming/{slug}/url`

Returns:
```json
{ "integration": "slack", "url": "https://yoursite.com/wp-json/zaplane/v1/incoming/slack" }
```

## HTTP Helpers

`IntegrationBase` provides three static helpers that wrap `wp_remote_request`.
They throw `\Exception` on WP_Error and return `[$body_array, $http_status_code]`.

```php
// GET
[ $body, $status ] = self::http_get( $url, [ 'Authorization' => 'Bearer ' . $token ] );

// POST (JSON body)
[ $body, $status ] = self::http_post( $url, [ 'email' => $email ], [ 'Authorization' => 'Bearer ' . $token ] );

// Any method
[ $body, $status ] = self::http_request( 'DELETE', $url, [
    'headers' => [ 'Authorization' => 'Bearer ' . $token ],
] );
```

## Registering an External Integration

From a separate WordPress plugin:

```php
// In your plugin's main file — fires before IntegrationLoader initializes
add_filter( 'zaplane_integrations', function ( array $integrations ): array {
    $integrations['mailerlite'] = [
        'file'  => 'mailerlite.php',
        'path'  => plugin_dir_path( __FILE__ ) . 'mailerlite.php',  // absolute path
        'class' => \MyPlugin\MailerLite::class,
    ];
    return $integrations;
} );
```

The `path` key is required for integrations outside the core `integrations/` directory.

## Rebuilding the Manifest

After any change to triggers, actions, schemas, `requires_connection`, or `supports_webhook`:

```bash
wp zaplane build:integration
```

This writes `assets/json/integrations.json` which the React editor reads via `ZaplaneGlobal.integrations`.

## Auth Type Reference

| `auth_type` | Use when | `get_auth_fields()` returns |
|------------|----------|---------------------------|
| `'none'`   | No auth needed (WordPress core, tools) | `[]` |
| `'api_key'` | Single token / API key | `['api_key' => [...]]` |
| `'basic'`  | Username + password | `['username' => [...], 'password' => [...]]` |
| `'oauth2'` | Full OAuth 2.0 flow | `['client_id' => [...], 'client_secret' => [...]]` |
| `'both'`   | User chooses method (e.g., OAuth or token) | Implement `get_available_auth_types()` and return per-type fields |

For `'both'`, also implement:

```php
public static function get_available_auth_types(): array {
    return [
        'oauth2'  => [ 'label' => 'OAuth 2.0', 'description' => 'Recommended.' ],
        'api_key' => [ 'label' => 'API Key',   'description' => 'Use a bot token.' ],
    ];
}
```
