## Architecture Overview

```
PHP (wp_localize_script in includes/admin/assets.php)
  └─ window.ZaplaneGlobal.integrations  ←  assets/json/integrations.json
                                             (regenerated by: wp zaplane build:integration)

React App
  ├─ Workflow Editor
  │   └─ FlowCanvas  →  ActionDrawer  →  SelectTab  →  ActionFieldRenderer
  └─ Connections Page  →  ConnectionTable / ConnectionDetails
```

## Global Data

`window.ZaplaneGlobal.integrations` is imported in every component via:

```js
import { integrations } from '@ZAPUtils/helper';
```

### Shape of each integration in `integrations.apps`

```
integrations.apps['slack'] = {
  slug:                'slack',
  name:                'Slack',
  icon:                'slack',
  category:            'app',
  requires_connection: true,      ← NEW — use this to decide if a connection picker is needed
  auth_type:           'both',    ← NEW — 'none' | 'api_key' | 'basic' | 'oauth2' | 'both'
  supports_webhook:    true,      ← NEW — whether incoming webhooks are available
  triggers: {
    message_received: { key, label, hook, schema: [...fields], outputs: ['main'] },
    app_mention:      { key, label, hook, schema, outputs },
    reaction_added:   { key, label, hook, schema, outputs },
    channel_created:  { key, label, hook, schema, outputs },
    file_shared:      { key, label, hook, schema, outputs },
  },
  actions: {
    send_message:      { key, label, schema: [...fields], outputs: ['main'] },
    send_dm:           { key, label, schema, outputs },
    create_channel:    { key, label, schema, outputs },
    invite_to_channel: { key, label, schema, outputs },
    set_topic:         { key, label, schema, outputs },
    add_reaction:      { key, label, schema, outputs },
    get_user_info:     { key, label, schema, outputs },
  }
}
```

### Schema field shape (used by ActionFieldRenderer)

```
{
  key:         'channel',
  type:        'text',          // text | textarea | number | email | url | password | select | date | condition_group
  label:       'Channel',
  placeholder: '#general or channel ID',
  required:    true,
  help:        'Optional help text shown below the field.',
  // select with static options:
  options:     [{ value: 'public', label: 'Public' }],
  // select with dynamic options (loaded via POST /zaplane/v1/dynamic):
  dynamic:     { query: 'channels', select: ['id', 'name'] },
}
```

## Redux — Connections Slice

File: `dev_zaplane/redux/Slices/connectionsSlice/connectionsSlice.js`

### Available thunks

| Thunk | Method | Endpoint | Purpose |
|-------|--------|----------|---------|
| `fetchConnections()` | GET | `/connections` | Fetch all connections for the current user |
| `fetchAuthFields({ app, authType? })` | GET | `/connections/auth-fields/{app}` | Get auth type and field definitions for an integration |
| `initOAuth({ app, name, credentials })` | POST | `/connections/oauth/init` | Start OAuth flow — returns `{ auth_url, state }` |
| `createTokenConnection({ app, name, authType, credentials })` | POST | `/connections` | Save an API key / basic auth connection |
| `testConnection(connectionId)` | POST | `/connections/{id}/test` | Test an existing connection |
| `deleteConnection(connectionId)` | DELETE | `/connections/{id}` | Delete a connection |
| `fetchSingleConnection(id)` | GET | `/connections/{id}` | Fetch one connection's details |
| `updateConnection({ id, payload })` | PUT | `/connections/{id}` | Update name / status / credentials |

### `fetchAuthFields` response shape

```
{
  app:                  'slack',
  auth_type:            'both',
  requires_connection:  true,
  available_auth_types: {
    oauth2:  { label: 'OAuth 2.0', description: '...' },
    api_key: { label: 'Bot Token', description: '...' },
  },
  auth_fields: {           // filled once the user picks an auth type
    bot_token: { type: 'password', label: 'Bot Token', placeholder: 'xoxb-...', required: true, help: '...' }
  }
}
```

### State shape

```
connections: {
  allConnection: [ { id, app, name, status, auth_type, last_tested_at, ... } ],
  authFields:    { app, auth_type, requires_connection, available_auth_types, auth_fields },
  oauthData:     null | { auth_url, state },
  connection:    {},     // single connection detail
  loading:       false,
  error:         null,
}
```

## Connecting from the Connections Menu

File: `containers/BackendDashboard/pages/connections/index.js`

### Current flow

1. User clicks **Create credential**
2. User picks an app — **the dropdown is currently hardcoded to `[{ value: 'slack', label: 'Slack' }]`**.
   This should be made dynamic — see the task below.
3. `fetchAuthFields({ app })` fires on app selection
4. If `auth_type === 'both'` → auth type buttons appear (OAuth / Bot Token / etc.)
5. User fills in the credential fields rendered from `authFields.auth_fields`
6. **OAuth path:** `initOAuth()` → open popup → listen for `zaplane_oauth_callback` postMessage → close popup → refresh list
7. **Token path:** `createTokenConnection()` → auto-tested → list refreshed

### Task: make the app dropdown dynamic

Replace the hardcoded `options` array with a list built from `ZaplaneGlobal.integrations`.
Only include apps where `requires_connection === true`.
The list is already available via `import { integrations } from '@ZAPUtils/helper'`.

## Feature: Inline Connection from the Workflow Editor

### What needs to be built

Currently when a user adds a Slack node to a workflow, there is no way to pick or create a
connection without leaving the editor and navigating to the Connections menu.

The goal: inside the **SelectTab** (the config panel for a node), when the selected integration
has `requires_connection === true`, show a **ConnectionSelector** UI that lets the user:

- Pick an existing connection from a dropdown
- Create a brand-new connection inline via a modal — without leaving the editor

The selected `connection_id` must be stored inside the node's data so the backend execution
engine can load the credentials automatically at runtime.

---

### Where to make changes

| File | What to do |
|------|-----------|
| `connectionsSlice.js` | Add a new thunk `fetchConnectionsByApp(appSlug)` that calls `GET /connections?app={slug}` — keep the existing `fetchConnections` as-is |
| `ConnectionSelector.js` | **Create new component** (see spec below) |
| `SelectTab.js` | Import `ConnectionSelector`, render it at the top when `selectedIntegration.requires_connection === true` |
| `ActionDrawer.js` | Pass `selectedIntegration` and `appSlug` down to `SelectTab`; include `connection_id` in the save payload |
| `useActionDrawer.js` | When re-opening a configured node, restore `connection_id` from `node.data.connection_id` via `setFieldValue` |

---

### Step-by-step implementation guide

#### 1. New Redux thunk — `fetchConnectionsByApp`

Add a new thunk alongside `fetchConnections` (do NOT modify `fetchConnections`):

- Name: `fetchConnectionsByApp`
- Action: `GET /connections?app={appSlug}`
- Returns: array of connections for that app
- Do NOT replace `allConnection` in state — store in a separate key, e.g. `appConnections`
  so the Connections page is not affected

#### 2. New component — `ConnectionSelector`

Create at: `actionDrawer/ConnectionSelector/ConnectionSelector.js`

**Props:**
- `appSlug` — string, e.g. `"slack"`
- `value` — number | null — currently selected `connection_id`
- `onChange(id)` — called when user picks or creates a connection

**Visual layout:**
```
Connection
┌──────────────────────────────────────┐  ┌───────┐
│  Select a connection…             ▼  │  │ + New │
└──────────────────────────────────────┘  └───────┘
✓ Connected
```

**Behaviour:**

On mount: dispatch `fetchConnectionsByApp(appSlug)` → populate the dropdown.

The dropdown options come from the `appConnections` slice key, filtered to `c.app === appSlug`.
Each option: `{ value: c.id, label: c.name }`.

Clicking **+ New** opens a modal (use the existing `WPModal` component).

Inside the modal:
1. A "Connection Name" text input (prefill with the app name if empty)
2. Call `fetchAuthFields({ app: appSlug })` on open to get auth type and field definitions
3. If `available_auth_types` has more than one entry → show method selector buttons
4. Render credential fields from `authFields.auth_fields`
5. **OAuth path:** dispatch `initOAuth({ app, name, credentials })` → open popup at `res.auth_url`
   → listen for `zaplane_oauth_callback` postMessage → call `fetchConnectionsByApp(appSlug)` →
   auto-select the newest connection → close modal
6. **Token path:** dispatch `createTokenConnection({ app, name, authType, credentials })` →
   call `fetchConnectionsByApp(appSlug)` → auto-select the new connection → close modal

After a successful creation call `onChange(newConnectionId)`.

Dispatch `resetAuthFields()` when the modal closes.

#### 3. Update `SelectTab.js`

Accept two new props:
- `selectedIntegration` — the full object from `integrations.apps[slug]` (has `requires_connection`)
- `appSlug` — string

At the very top of the rendered output, before the action type select:

```
if (selectedIntegration?.requires_connection === true)
  → render <ConnectionSelector appSlug={appSlug} value={values.connection_id} onChange={(id) => setFieldValue('connection_id', id)} />
```

#### 4. Update `ActionDrawer.js`

Two changes:

**A — Pass new props to SelectTab:**

Compute `selectedIntegration` from `getIntegration(mode, selectedItem)` and pass it, along with
`appSlug={selectedItem?.id}`, into the `<SelectTab>` render inside the ZAPTab content.

**B — Include `connection_id` in the save payload:**

Inside `handleContinue`, add `connection_id: values.connection_id ?? null` to the payload object
that gets passed to `updateNodeData` / `createActionNode`.

```
payload = {
  app,
  name,
  event,
  hook,
  connection_id: values.connection_id ?? null,   ← ADD THIS
  config: { ...field values }
}
```

#### 5. Update `useActionDrawer.js`

When restoring a node that was already configured (the `useEffect` block that reads `node.data`),
add one line to restore the saved connection:

```
if (node.data.connection_id) setFieldValue('connection_id', node.data.connection_id);
```

This ensures that when a user re-opens a Slack node the previously chosen connection is
pre-selected in the `ConnectionSelector` dropdown.

### Data flow diagram

```
User opens ActionDrawer for a Slack node
  → useActionDrawer detects mode="app", selectedItem={id:'slack', name:'Slack'}
  → ActionDrawer computes selectedIntegration = integrations.apps['slack']
  → selectedIntegration.requires_connection === true
  → SelectTab renders ConnectionSelector at the top

ConnectionSelector mounts
  → fetchConnectionsByApp('slack')  →  GET /connections?app=slack
  → shows existing connections in dropdown
  → if value (connection_id) already set → shows "✓ Connected"

User clicks "+ New"
  → modal opens
  → fetchAuthFields({ app: 'slack' })
  → user picks "Bot Token" auth type
  → fills in xoxb-... token
  → createTokenConnection(...)  →  POST /connections
  → auto-selects new connection → onChange(newId) → setFieldValue('connection_id', newId)
  → modal closes

User selects action type → fills config fields → clicks Continue
  → handleContinue builds payload:
    { app:'Slack', event:'send_message', connection_id: 42, config:{channel,text} }
  → updateNodeData(payload) → saved to ReactFlow node.data

Workflow saved → graph stored in DB with node.data.connection_id = 42

At execution time (PHP — already implemented):
  → Automation::inject_credentials($node)
     → ConnectionManager::get_execution_credentials(42)
     → $node['_connection_credentials'] = { access_token: '...' }
  → Slack::execute_node($node, $input)
     → $token = $node['_connection_credentials']['access_token']
     → wp_remote_post to Slack API
```
